### 1.3 术语

| 术语 | 定义 |
|---|---|
| Memory | 从原始对话抽取的结构化事实或事件，携带时间及来源 |
| 候选记忆 | 根据问题从指定对话的完整记忆集合自动召回的记忆 |
| 有效记忆 | 在给定问题和时间条件下，可用于支持答案的记忆 |
| RETAIN | 比较范围内事实兼容，相关记忆仍予保留 |

| gold | 仅供评测使用的参考答案、证据或关系标注 |

## 2. 系统概述与范围

### 2.1 问题与目标

长期对话中的计划、职业和偏好会变化。仅按相关性检索可能将陈旧状态用于当前回答。系统应把结构化记忆、问题驱动检索、关系判断和有效性解析连接起来，并让用户回溯原始证据。

处理流程：

`LoCoMo 导入 → 结构化记忆构建 → 持久化 / JSON 导出 → 问题与时间条件 → 候选检索 → 关系判断 → 有效记忆解析 → 回答及证据展示`

### 2.2 用户与外部依赖

| 参与者 | 任务 |
|---|---|
| 研究者 / 演示用户 | 选择对话、浏览记忆、提出问题、检查答案与证据 |
| 开发 / 数据人员 | 导入数据、构建记忆、配置模型、排查失败 |
| 测试 / 评测人员 | 执行测试、比较基线、导出结果和复现实验 |
| 外部模型服务或本地预训练模型 | 提供可配置的抽取、嵌入、关系判定或生成能力 |

系统为本地可运行 Web 应用；批量构建和评测可由命令行执行。单用户课程演示不要求账号体系、多租户或公网部署。不得训练大语言模型，不扩展为通用聊天系统。

### 2.3 范围与交付

必做：课程指定 6 段 LoCoMo（4 dev + 2 test）、自动结构化记忆构建、统一 JSON、Web 记忆和证据展示、自动检索、动态关系与有效性解析、基于有效证据回答、三项指标及两类基线。

基础冲突标记和证据保留纳入本项目范围。复杂冲突消解、Graph Memory、多跳、压缩、自适应检索及复杂时间推理属于可选增强，不作为本 SRS 的核心验收前提；与 M2“完成所有 Bonus”的措辞差异须按第 10 节评审。

M3 交付本文；M4 目标为必做链路、设计说明、源代码、可运行 Web、示例 JSON、测试记录和中期展示；M5 完成独立测试与完整对照分析、最终报告和展示。评测工具应在 M4 可运行，不将最终结果预写为已完成。

## 3. 数据需求

### 3.1 数据集与隔离

- 使用课程选定的 6 段对话，准确 conversation ID、划分及标注版本待课程材料确认，不自行假定名单。
- 数据清单须记录数据来源、版本或文件摘要、conversation ID、split、导入时间。
- dev 用于规则、提示词和参数调试；test 可按同一冻结流水线构建 Memory，但其答案和动态标注不得用于调参。
- 抽取、索引和回答仅使用原始对话及问题允许的时间上下文；不得将 gold 答案、证据列表或事件摘要标注作为推理输入。事件摘要可用于离线人工核查，须与系统输入隔离。
- 所有标识在其命名空间内唯一；证据使用 `(conversation_id, session_id, turn_id)` 联合定位，禁止跨对话混用。

### 3.2 逻辑数据契约

以下为统一导出和查询结果的逻辑契约；物理存储方式不在本文限定。

| 对象 | 字段与约束 |
|---|---|
| Conversation | `conversation_id`、`split`、`dataset_version`、sessions |
| Session | `session_id`、原始时间字符串、可解析的标准时间或 null、turns |
| Turn | `turn_id`、`speaker`、`text`，内容保留原始值 |
| Memory | `memory_id`、`conversation_id`、`content`、`entity`、`attribute`、`value`、`session_time`、`time_expression`、`event_time`、`sources`、`record_status` |
| Relation | `relation_id`、`query_id`、`from_memory_id`、`to_memory_id`、`type`、`reason`、`evidence_memory_ids` |
| QueryResult | `query_id`、问题、对话 ID、时间条件、实际截止时间、候选及分数、关系、逐条有效性、有效 ID、冲突 ID、答案、引用、状态、运行配置 |

Memory 必填：ID、对话 ID、非空 content、非空 sources、record_status。entity/attribute/value 为可空的结构化信息，无法抽取时保留 content，不能猜测填充。sources 为非空数组，每项含 session_id 和 turn_id，可支持跨轮证据。record_status 仅描述数据记录质量（`ready` / `needs_review`），不代表全局有效性。

session_time 为标准时间或 null；保留原始会话时间。time_expression 保留“last Friday”等原文或 null；event_time 是规范化的事件日期/时间或 null，须记录精度与推导依据。未知日期不能强制补齐日期或时区。

查询级有效性为 `effective`、`historical`、`conflict`、`uncertain`、`irrelevant`，须附理由；原始 Memory 不因一次查询被改写为永久失效。关系 type 为四类标签；无法判断时不伪造关系，另在解析结果中记录 uncertain 及原因。

### 3.3 JSON 示例

以下为课程 Caroline 示例的字段表达，仅说明契约，不代表已抽取的数据：

```json
{
  "schema_version": "0.1",
  "dataset_version": "pending-course-confirmation",
  "memories": [
    {
      "memory_id": "conv26_D19_1",
      "conversation_id": "conv-26",
      "content": "Caroline passed the adoption agency interviews.",
      "entity": "Caroline",
      "attribute": "adoption_status",
      "value": "passed adoption agency interviews",
      "session_time": "2023-10-22T09:55:00",
      "time_expression": "last Friday",
      "event_time": null,
      "sources": [{"session_id": "19", "turn_id": "D19:1"}],
      "record_status": "ready"
    }
  ]
}
```

此例未推断事件日期或时区。完整导出须附关联来源数据或能够定位来源的数据版本清单，并记录抽取模型、提示词版本和构建配置。

## 4. 功能需求

下列 FR 均为必做需求。验收方式见第 8 节。

| 编号 | 需求与验收条件 |
|---|---|
| FR-01 数据导入 | 系统应导入课程 LoCoMo 对话，保持会话、轮次、说话人和原文对应；校验重复 ID、必填项及格式。失败时指出记录位置，不将失败任务标记为成功。重复导入同一数据版本不得静默产生重复记录。 |
| FR-02 记忆构建 | 系统应从原始对话自动构建 Memory，覆盖人物、事件、时间、状态信息；每条记忆满足第 3 节字段约束并可回溯来源。不能只加载人工写好的演示记忆来替代抽取。 |
| FR-03 构建任务反馈 | 系统应报告任务状态、成功和失败数量及可定位的失败信息；重试不得重复写入已完成记忆，部分完成须明确标识。 |
| FR-04 统一导出 | 系统应按对话或整个已构建集合导出 UTF-8 JSON，包含 schema_version、记忆及数据/构建版本；导出须可重新解析，引用完整且 ID 无重复。 |
| FR-05 记忆浏览 | Web 应按所选对话列出记忆，展示内容、实体、时间及来源；支持按实体或关键词筛选和分页/分批加载，空集合显示明确提示。 |
| FR-06 证据回溯 | 点击记忆或答案引用应展示对应原始轮次及会话信息；存在多来源时全部可查看。无法定位时报告错误，不展示其他轮次替代。 |
| FR-07 问题输入 | 系统应接收 conversation_id、非空自然语言问题、可选时间截止条件和正整数 top_k；无效参数或未构建数据应返回可理解的错误。 |
| FR-08 自动检索 | 系统应从指定对话可用历史的完整记忆集合自动召回前 K 项，返回 ID、排序分数和来源；不足 K 条时返回实际数量。不得用 gold 证据预先限定候选。 |
| FR-09 关系判定 | 系统应按第 5 节对相关候选作比较，输出适用的 RETAIN / UPDATE / SUPERSEDE / CONFLICT、关系端点、理由和证据；对不同实体或无关属性不强行建立替代关系。 |
| FR-10 有效性解析 | 系统应结合问题、时间和关系，为候选提供有效性与理由，并返回有效及冲突集合；保留历史来源，不因当前查询删除原始记忆。 |
| FR-11 回答生成 | 系统应根据解析结果生成答案，提供支撑事实的 Memory 引用；证据不足返回 insufficient_evidence，存在影响结论且无法消解的冲突返回 unresolved_conflict 并说明分歧。不得把未决冲突表述为确定事实。 |
| FR-12 解析展示 | Web 应展示问题、实际时间截止、候选、关系、理由、有效/历史/冲突状态、最终答案及证据；加载和失败状态可见。关系可用列表或时间线表达，不强制使用图数据库。 |
| FR-13 评测执行 | 系统应支持批量执行 Full Text、Vector RAG 和本方法，保存逐题预测、证据、关系、错误、运行配置和聚合指标；gold 仅在评分阶段使用。 |

## 5. 状态与时间业务规则

### 5.1 关系判定

| 编号 | 规则 |
|---|---|
| BR-01 | 先判断实体、属性/事件、时间和查询语义是否可比较。新出现的事实不必然替代旧事实。 |
| BR-02 | RETAIN 表示比较的相关事实兼容、无更新或替代依据；对单条候选可以直接标记 effective，不制造虚假的双节点关系。 |
| BR-03 | UPDATE 用于同一过程的阶段推进，如 researching → applied → passed interviews；当前状态查询采用适用时间内的新阶段，保留旧阶段用于历史问题。方向为旧 → 新。 |
| BR-04 | SUPERSEDE 用于新事实替换同一查询范围内的旧状态。课程 Gina 失业→网店开业示例仅针对当前职业/业务状态，不能据此推断她从未失业，或所有职业事实互斥。方向为旧 → 新。 |
| BR-05 | CONFLICT 要求同一语义及重叠时间条件下不能同时成立，且缺乏消解依据。事实仅发生在不同时间不构成冲突；冲突关系语义对称，输出避免重复。 |
| BR-06 | 只有来源时间更晚而没有事件时间或语义依据时，不得自动把新陈述视为真实。不能消解则标记 conflict/uncertain，保留双方证据。 |
| BR-07 | 关系循环、引用缺失或相互矛盾的解析结果须报告为未决，不得任意选取一个节点作为确定答案。 |

### 5.2 时间语义

- **BR-08 默认当前**：“当前”指所选对话可用历史的末端，不能使用运行机器日期替代对话时间；结果应显示实际截止条件。
- **BR-09 历史截止**：显式截止时间限制可使用的来源会话；晚于截止的陈述不得进入检索、推理或答案。语义性历史问题须结合事件时间解析，若无法可靠确定时间范围则返回澄清/不确定提示。该保守约定用于避免未来信息泄漏。
- **BR-10 事件与记录分离**：会话时间表示何时被陈述，事件时间表示何时发生。无法解析相对时间时保留原文和 null，不以记录时间伪装事件时间。
- **BR-11 历史有效性**：被更新的记忆仍可能是较早时间点的有效证据；不同查询不得互相污染有效性结果。
- **BR-12 无证据**：无候选或候选均不支持答案时，返回明确的证据不足状态；不得使用模型外部知识补成对话事实。

复杂时间推理为 Bonus，但默认截止、基本日期比较、历史保留及不确定时间处理属于必做正确性边界。

## 6. 主要用例

### UC-01 导入并构建

参与者：数据人员。前置：存在合法数据文件与可用构建配置。

1. 提交数据并选择记录的数据版本及划分。
2. 系统校验输入、保留原始来源并创建构建任务。
3. 系统逐批抽取、校验和保存 Memory，报告进度。
4. 用户浏览结果并导出 JSON。

后置：成功记忆可回溯，失败部分有记录。异常：格式错误终止对应导入；模型失败标记任务部分失败并允许重试；不能把部分输出冒充完整集合。

### UC-02 浏览和核查证据

参与者：演示用户。前置：所选对话已构建。

用户选择对话并筛选记忆，打开详情，查看全部来源轮次。系统显示原文与时间。空结果提示调整条件；来源损坏显示定位错误。后置：浏览不修改原始记录或查询级状态。

### UC-03 查询并解析

参与者：演示用户。前置：存在可检索记忆。

1. 选择对话，输入问题、可选截止时间和 K。
2. 系统校验输入，依据时间范围从完整记忆集合检索。
3. 系统判定适用关系并计算查询级有效性。
4. 系统基于有效证据回答，返回引用和状态。
5. 用户检查候选、更新链、未决冲突和原始证据。

后置：保存可核查的查询结果。分支：空问题拒绝执行；无证据明确说明；冲突展示双方；外部服务失败返回 request_id 和失败阶段，不显示伪造答案。

### UC-04 批量评测

参与者：评测人员。前置：数据划分已冻结，标注和配置可用。

加载问题集，按同一配置运行三个方法，保存逐题输出，再加载 gold 评分，汇总指标及错误。单题失败保留为失败记录，不静默剔除；标注缺失则标记不可评分及原因，不生成虚构指标。

## 7. 接口与非功能需求

### 7.1 外部接口契约

本节规定逻辑操作，不强制 HTTP 路径；具体路由和技术栈在设计文档中确定。

| 操作 | 输入 | 输出 |
|---|---|---|
| 导入 / 构建 | 数据文件、版本、划分、配置 | task_id、状态、校验错误 |
| 查询任务 | task_id | 阶段、进度、成功/失败数、错误摘要 |
| 列出记忆 | conversation_id、筛选、分页 | 记忆列表、总数、分页信息 |
| 证据详情 | Memory ID / 来源联合 ID | 记忆、原文、会话与轮次 |
| 导出 | 对话范围、schema 版本 | JSON 文件及版本信息 |
| 问答 | conversation_id、question、可选 as_of、top_k | 第 3.2 节 QueryResult |
| 批量评测 | 划分、方法、配置 | run_id、逐题输出、指标、失败统计 |

错误至少包含 `code`、`message`、`request_id`；校验、数据不存在、模型不可用和超时应能区分。模型接口配置须记录 provider/model、超时、提示词版本和参数；API Key 仅由服务端读取。

### 7.2 非功能需求

| 编号 | 要求与验证方式 |
|---|---|
| NFR-01 可运行性 | 仓库提供依赖、配置示例、数据获取和启动说明；另一成员能依说明启动 Web 并完成 UC-02/03。模型凭据不足时明确提示，不宣称完整运行成功。 |
| NFR-02 可追溯性 | 所有输出引用均能定位原始轮次；验收样例中的失效引用数须为 0。 |
| NFR-03 可靠性 | 外部服务须有有限超时和有限重试，不无限阻塞；记录最终失败阶段。具体秒数和重试次数在配置冻结时记录。 |
| NFR-04 可复现性 | 保存代码版本、数据摘要、模型、提示词、检索 K、随机参数及原始预测；外部模型不保证逐字重复，评测应能追踪差异。 |
| NFR-05 安全性 | 不将真实密钥写入仓库、浏览器响应或日志；对话文本按不可信数据处理，不能借其指令泄露配置或覆盖系统规则；页面按文本安全渲染。 |
| NFR-06 交互性能 | 拟定验收目标：单用户、本地已构建 6 段数据，普通列表/详情请求连续 20 次 P95 ≤2 秒；首次构建与外部模型调用不计入此指标。验收记录硬件、数据量和缓存条件。 |
| NFR-07 状态反馈 | 拟定目标：操作后 1 秒内显示加载/任务状态；模型调用时展示等待，超时明确失败。端到端问答耗时记录 P50/P95，阈值待模型选定后评审。 |
| NFR-08 可维护性 | 数据导入、抽取、检索、解析、生成和评测具有明确模块边界；框架和模型可配置，逻辑不依赖硬编码的课程答案。 |

### 8.2 指标定义

**QA F1**：优先采用课程指定评分程序。若未提供，临时使用 token overlap F1：对规范化预测和参考答案计算 token 多重集合交集，P=交集数/预测 token 数，R=交集数/参考 token 数，F1=2PR/(P+R)，无交集为 0。多参考取最高分，逐题宏平均。规范化暂定小写、移除英文标点及冠词、合并空白；tokenizer、空答案和不可回答题规则须随评分脚本版本固定。课程规则到位后统一替换并重跑，不混合口径。

**证据 Recall@K**：以来源轮次为临时统一比较单位。设 gold 证据集合 G，前 K 条检索 Memory 的来源轮次并集 R，则 Recall@K=|G∩R|/|G|。K 指 Memory 条数，轮次比较须含对话/会话标识；去重后计数。暂定报告 K=5、10；G 为空的题标记不可评分并报告数量，不直接记为 1。若课程按 Memory 评分，建立基于来源的确定映射并以课程口径为准。

**状态判断准确率**：优先以课程标注的关系实例为单位，Accuracy=标签完全匹配数/可评分 gold 实例数。遗漏 gold 端点或关系按错误计，不能仅统计已成功召回的关系；UPDATE/SUPERSEDE 检查方向，CONFLICT/RETAIN 按对称关系规范化。若课程合并 UPDATE/SUPERSEDE，评分时显式映射。输出多余关系另外报告误报数量，避免单一准确率掩盖过度预测。标注单位及 Memory 映射尚待确认。

模型失败/超时须纳入总题数和失败率；有 gold 的失败题按零分处理。仅因缺 gold 而不可评分的题单列，不得混同系统失败。

### 8.3 基线与实验公平性

| 方法 | 输入与行为 |
|---|---|
| Full Text | 同一对话、同一时间范围的完整原始历史作为上下文，无记忆检索与状态解析 |
| Vector RAG | 与本方法相同的抽取记忆、向量检索与 K，直接将候选用于生成，不运行状态解析 |
| 本方法 | 相同候选检索配置，增加状态关系与有效性解析后生成 |

三个方法使用同一问题集及尽可能一致的生成模型和参数；Full Text 超过上下文限制时须报告限制及处理策略，不静默截断后仍称为完整全文。Full Text 无检索 Recall@K，两个基线无显式状态判定时状态准确率记 N/A，不伪造可比较结果。

目标是改善动态问题的回答质量；“优于基线”是待验证假设，不是课程给出的固定数值门槛。报告均值、有效样本数、失败数、逐题输出、失败案例和相对基线变化；尚无依据设定 F1/Recall/Accuracy 的绝对达标线。
