## 1. 业务需求（Business Requirements）

### 1.1 背景与机遇

大语言模型（LLM）驱动的智能体正在从「单轮问答」走向「长程、多会话、任务导向」的长期助手。此类智能体必须在横跨数周、数十个会话的对话历史之上持续维护对**用户状态、计划与偏好**的理解，才能给出正确、连贯且可追溯的回答。这催生了对**长期对话记忆（long-term conversational memory）**的强烈需求。

LoCoMo（Long-Term Conversational Memory，ACL 2024）基准系统性地量化了这一能力缺口：即便在最先进的模型上，基于全文或向量检索的记忆方案在需要追踪**跨会话事实演化**的问题上，回答质量仍显著不足。这为构建一个**具备动态状态解析能力的记忆系统**提供了明确的研究与工程机会。

### 1.2 问题陈述（Problem Statement）

**核心矛盾：检索到「相关」≠ 检索到「当前有效」。**

在长程、多轮对话中，用户的**状态、计划与偏好会随时间持续漂移（state drift）**。例如：一个人 1 月失业于某公司，3 月却开了网店；一段关系从「正在申请」演化为「已经通过」。传统的**向量检索（vector RAG）**只度量语义相关度，它无法区分：

- 仍为真、仍有效的**当前状态（current / valid state）**；
- 已被后续信息**更新（UPDATE）**或**替代（SUPERSEDE）**的**陈旧状态（stale state）**；
- 无法同时成立、需要消解的**冲突事实（conflicting facts）**。

其结果是：系统会同时召回「当前状态」与「已被后续信息更新掉的旧状态」，进而**基于过时记忆作答**，造成事实性错误或错误决策。这属于典型的**记忆时效性（memory temporal validity / staleness）**问题，而非单纯的检索召回率问题。

**本项目要解决的问题可形式化表述为：**

> 给定跨会话对话历史 *D*、自然语言查询 *q* 与从历史中抽取的结构化记忆集合 *M*（含实体、事件、时间戳与状态），系统需：(1) 检索与 *q* 相关的候选记忆 *M_q*；(2) 判定候选记忆之间的状态关系 *r* ∈ { RETAIN, UPDATE, SUPERSEDE, CONFLICT }；(3) 据此解析出**当前有效记忆集合 M_q^eff**；(4) 基于 *M_q^eff* 生成答案并给出可追溯的证据。

### 1.3 业务目标与成功准则

| 目标 | 描述 | 可度量的成功准则 |
|---|---|---|
| 提升回答正确性 | 基于当前有效记忆而非陈旧记忆作答 | QA **F1** 优于全文与向量检索基线 |
| 保证证据召回 | 召回支撑回答的相关记忆 | 证据记忆检索 **Recall@K** 达标 |
| 准确的动态判定 | 正确识别记忆间状态关系 | 状态关系判定**准确率**达标 |
| 可解释、可追溯 | 让记忆、关系与解析过程可见 | Web 端可展示证据与解析链路 |

## 2. 项目愿景（Vision of the Solution）

### 2.1 愿景陈述

> 让 AI 智能体在长程、多会话对话中，「记住的是最新事实，而不是被过时记忆误导」。

将「静态的向量检索」升级为**可追溯、可解析状态演化的动态记忆系统**：不仅召回相关历史，还能判断哪些记忆已过时、被替代或相互冲突，从而始终基于**当前有效记忆**给出正确回答。

### 2.2 核心价值主张

1. **结构化记忆构建**：从 LoCoMo 原始对话中抽取人物 / 事件 / 时间 / 状态，生成带来源的结构化 Memory，并统一导出为 JSON。
2. **查询驱动的动态状态解析**：以「回答当前问题」为导向，判定候选记忆间 RETAIN / UPDATE / SUPERSEDE / CONFLICT 关系，定位当前有效记忆。
3. **基于有效记忆的回答与证据**：仅依据当前有效 Memory 生成答案，并在 Web 端展示记忆、原始证据（会话 / 轮次）与完整解析过程。

### 2.3 主要特性概览

| 特性 | 类别 | 说明 |
|---|---|---|
| 结构化记忆构建 | 必做 | 抽取人物 / 事件 / 时间 / 状态 → 结构化 Memory |
| 统一 JSON 导出 | 必做 | 所有 Memory 导出为统一 JSON 格式 |
| Web 记忆可视化 | 必做 | 查看结构化记忆 + 原始证据 |
| 记忆检索 | 必做 | 给定问题，检索相关候选 Memory |
| 状态关系判定 | 必做 | 判定 RETAIN / UPDATE / SUPERSEDE / CONFLICT |
| 有效记忆解析 + 回答 | 必做 | 确定有效 Memory，据此生成答案 |
| Web 状态解析展示 | 必做 | 展示历史 Memory 及其关系与解析过程 |
| 冲突消解 / 多版本保留 | Bonus | 更复杂的冲突消解与多版本保留 |
| Graph Memory / 多跳建模 | Bonus | 图记忆与多跳关系建模 |
| Memory 合并与压缩 | Bonus | 记忆合并与压缩 |
| 自适应检索 / 时间推理 | Bonus | 自适应检索或复杂时间推理 |

### 2.4 假设与依赖

- **数据**：依赖 LoCoMo 官方数据集（[github.com/snap-research/locomo](https://github.com/snap-research/locomo)），含 QA、证据轮次与事件摘要标注。
- **任务标注**：课程统一从所选 QA 中筛选「状态变化」类问题，并标注相关 Memory、其关系与最终有效 Memory。
- **模型**：以调用大模型 API 或复用预训练模型完成抽取、判定与生成，**不训练大模型**。
- **运行形态**：以本地可运行的 Web 应用交付，**不接入真实生产环境**。

## 3. 范围与限制（Scope & Limitations）

### 3.1 范围内（In-Scope）

1. **数据与记忆构建**：选用 6 段 LoCoMo（4 段 dev + 2 段 test），从原始对话提取人物 / 事件 / 时间 / 状态，构建结构化 Memory（Memory ID · Content · Entity/Event · Timestamp · Source Session/Turn · State），支持统一 JSON 导出与 Web 可视化。
2. **动态维护与查询**：对输入 QA 检索相关历史 Memory，判定 RETAIN（保留）/ UPDATE（更新）/ SUPERSEDE（替代）/ CONFLICT（冲突），确定当前有效 Memory 并生成回答；Web 端展示相关证据与状态解析过程。

**交付物**：可运行 Web 应用 + 完整源代码 + 结构化 Memory JSON + 测试结果 + 项目报告。

### 3.2 可选增强（Bonus）

- 复杂冲突消解与多版本保留
- Graph Memory / 多跳关系建模
- Memory 合并与压缩
- 自适应检索 / 复杂时间推理

### 3.3 范围外（Out-of-Scope）

- 不训练大语言模型；
- 不构建通用对话系统；
- 不接入真实生产环境；
- 不承担超出 LoCoMo 数据范围之外的领域适配。

## 4. 数据与评测（Data & Evaluation）

### 4.1 数据来源与选段

- 数据与代码：LoCoMo（[github.com/snap-research/locomo](https://github.com/snap-research/locomo)）。
- 从官方 10 段长对话中选 **6 段**：4 段 dev（开发调试）+ 2 段 test（最终评测），其余 4 段作扩展评测。
- 每段平均约 **588.2 轮、27.2 个会话、约 1.66 万 Token**，含 QA / 证据轮次 / 事件摘要标注。

### 4.2 评测指标

| 指标 | 度量内容 |
|---|---|
| 问题回答 **F1** | 最终答案质量 |
| 证据记忆检索 **Recall@K** | 支撑回答的相关记忆召回能力 |
| 动态状态更新判断**准确率** | 状态关系判定（RETAIN / UPDATE / SUPERSEDE / CONFLICT）正确率 |

### 4.3 对照方法（Baseline）

| 方法 | 说明 |
|---|---|
| **Full Text** | 全文作为上下文，不做检索 |
| **Vector RAG** | 检索相关记忆但不做状态关系判断 |

> 本系统的增量价值体现在：在等价检索基础上，显式建模**状态演化**，将「召回相关」提升为「召回当前有效」。

## 6. 约束与风险（Constraints & Risks）

| 风险 | 影响 | 对策 |

| 数据量大（每段 ~588 轮） | 抽取 / 检索耗时、链路难跑通 | 先用 4 段 dev 尽早跑通流水线，再上 2 段 test 复测 |

## 附录 A：术语表（Glossary）

| 术语 | 含义 |
|---|---|
| **LoCoMo** | Long-Term Conversational Memory 基准（ACL 2024），提供长程多会话对话数据与 QA / 证据 / 事件摘要标注 |
| **Memory** | 从对话中抽取的结构化记忆单元（含实体、事件、时间、来源与状态） |
| **状态漂移（State Drift）** | 用户状态 / 计划 / 偏好在长程对话中持续变化的现象 |
| **陈旧记忆（Stale Memory）** | 已被后续信息更新或替代、不再代表当前事实的记忆 |
| **有效记忆（Valid Memory）** | 当前时间点仍为真、应作为回答依据的记忆 |
| **RETAIN / UPDATE / SUPERSEDE / CONFLICT** | 记忆间四种状态关系：保留 / 更新 / 替代 / 冲突 |
| **Recall@K** | 证据记忆检索召回率（前 K 个结果命中比例） |
